本页保留 **首轮集显预算** 的历史数据和未达项。负责人随后将 v7 默认目标提升为笔记本 GTX 1060；当前配置与新一轮验证见[新预算记录](village-streaming-v7-1060-validation.md)。不能使用新门槛追认本页旧指标通过。

2026-09-16。制作、命令和口径见[工程说明](../engineering/village-streaming-v7.md)。`[已实现]` 独立 v7 预览、七区加载、四档 LOD、预算选择和遥测；正式与无参数默认预览仍为 v6。目标是为继续增加全村资产留出空间，本轮没有增加建筑、改变通路或剧情。

## 设备与口径

实测设备为 **NVIDIA GeForce RTX 2080 Ti**，Godot 4.6.3 .NET / Compatibility，实际渲染分辨率为 1280×720、1600×900、1920×1080。GPU 结果不能替代中低端集显验收。开启垂直同步；FPS 接近 60 不代表 GPU 满载性能或集显可以达到 60 FPS。

整帧 `primitives` 包含角色、地形和阴影的重复提交，是比单次可见外景三角形更宽的统计；`drawCalls` 包括地形、角色、UI 和额外 pass。选择器的 `Meshes` 为外景网格实例，`Batches` 为外景主 pass surface 数，二者都不能当作整个渲染器的计数。`RenderTotalObjectsInFrame` 也不是去重后的可见网格实例数。

探针覆盖九个关键点及 47 个有效网格落点，共 56 点 × 8 个非直角方向 × 3 档分辨率 = 1,344 样本。原始逐帧记录按稳定、加载、住宅转场、连续移动转镜、截图阶段区分。截图阶段含 PNG 回读和写盘，不计入游戏 FPS；游戏阶段的加载和转场尖峰仍保留。首次场景加载时间是本机进程内测量，未清空操作系统文件缓存，不能标成目标硬件冷盘加载。

## 最终矩阵与对照

`[已实现]` 最终 v7：`outputs/village-v7/20260916-112758-probe/results.json`，**1,344 样本／3,052 项检查通过**。对照 v6：`outputs/village-v7/20260916-112254-baseline/results.json`，同样 1,344 样本。汇总：`outputs/village-v7/final-summary.json`，可用 `scripts/tools/summarize_village_v7.py` 从原始记录重新生成。两次性能矩阵顺序执行，期间没有并行编译、资源导出或其他引擎测试。

| 分辨率 | 整帧图元峰值 v6 → v7 | 整帧 draw call 峰值 v6 → v7 | GPU 平均 ms v6 → v7 | GPU p95 ms v6 → v7 |
| --- | ---: | ---: | ---: | ---: |
| 1280×720 | 1,748,567 → 261,692 | 2,402 → 159 | 3.90 → 3.37 | 5.18 → 6.42 |
| 1600×900 | 1,762,463 → 265,616 | 2,402 → 159 | 4.14 → 3.85 | 5.14 → 5.26 |
| 1920×1080 | 1,763,759 → 265,616 | 2,402 → 159 | 3.44 → 4.03 | 5.51 → 5.05 |

1080p 图元峰值约下降 **84.9%**，draw call 峰值约下降 **93.4%**；本机 GPU 平均时间并未在每档分辨率都改善，不能宣传等比例提速。显存峰值 v6 → v7 为 214.16 → 279.62 MiB、234.06 → 299.52 MiB、258.98 → 326.47 MiB。低模常驻、近景包、缓存顶点与动态 HLOD 换取更低提交量，存在显存开销。

每档分辨率各有 262 个 near 样本、186 个 wide 样本，整帧三角面超限样本 **0**。near 整帧峰值为 181,534／185,198／185,198，wide 为上表峰值。外景选择成本峰值为 near **99,974 三角形／12 实例／24 surfaces**、wide **176,890／3／32**（各维度峰值分别统计）。加载／连续转镜在室外逐帧记录的最大值仍为 265,616，低于 360k 过渡目标。住宅内部属于已有独立场景，最高 476,268 不计作村庄外景通过；原始记录包含 `interior` 标记，未删去该数据。

主角家门前八方向的 `homeLod` 均为 0；广场八方向的 `shopLod` 均为 0。保留近景材质后，使用 LOD3 独立外壳参与阴影 pass，避免高模屋瓦、构件再次全量提交。最终抽查主角家、广场、双桥等截图，确认这两处近景材质与外壳仍存在；远处建筑和树冠有明显简化，不能替代负责人视觉终验。

## 帧时与加载尖峰

以下是稳定采样阶段的实际帧间隔，含镜头角度切换后的四帧；不是 `FramePostDraw` 局部等待时间。最低 FPS 为单帧倒数，不是 1% low。

| 分辨率 | 平均 FPS v6 → v7 | 最低瞬时 FPS v6 → v7 | p95 帧时 ms v6 → v7 |
| --- | ---: | ---: | ---: |
| 1280×720 | 60.32 → 60.17 | 36.19 → 30.02 | 16.93 → 17.03 |
| 1600×900 | 60.31 → 60.18 | 23.09 → 22.65 | 16.91 → 17.00 |
| 1920×1080 | 60.30 → 59.46 | 33.45 → 4.88 | 16.97 → 17.15 |

`[已实现]` 1080p 连续物理移动加每帧 7° 水平转镜 252 帧：平均 **16.69 ms / 59.91 FPS**、p95 **17.23 ms**、最慢 **20.72 ms**。全记录控制器最长 **50.93 ms**；稳定阶段最慢 **204.84 ms**、加载阶段 **512.36 ms**、住宅转场 **1,748.37 ms**。后两者分别发生在初次加载、住宅内部恢复；不得省略这些尖峰后声称“无卡顿”。住宅转场合并进 1080p 全过程统计时，平均 57.38 FPS、最低瞬时 0.57 FPS；全过程 p95 为 17.15 ms。截图阶段最慢 826.54 ms 单列，未计入上述游戏帧时。

本次初次场景及近景等待为 v7 **7,208.89 ms**，v6 **2,200.82 ms**。此前本机多轮首次加载差异很大，因此本轮既不能证明冷启动改善，也不能把异步请求等同于没有主线程加载成本。`[计划]` 继续优化首次资源准备、转场及资源上传尖峰，并在目标集显复测；严格稳定 60 FPS 目标尚未验收。

## 验收边界

- `[计划]` 中低端集显的 GPU 平均 ≤14 ms／p95 ≤16.7 ms 与冷加载验收。本机独显结果不能替代。
- `[计划]` 整帧 draw call ≤24/32/36 的目标尚未达到。当前预算约束的是外景提交，Terrain3D、角色与其他 pass 仍有额外调用；整帧可见网格上限也不能由选择器计数宣称通过。
- `[计划]` 负责人连续游玩的视觉与手感终验。近处建筑保留纹理；远景外壳、树冠密度、阴影距离和背景材质有明显简化，需在目标硬件预算内权衡。
- `[固定约束]` 自动网格采样不能证明所有连续点位、任意未来相机配置或以后增加的资产都满足整帧预算。新增资产必须重新导出清单并重跑矩阵。
- `[固定约束]` 含本机角色的全部截图仅留 `outputs/`，不提交、分发或导出。没有推送或导出游戏。

此前迭代日志保留供排错：早期全模型塌缩破坏薄构件；惰性 Snapshot 序列化在枚举期间遇到选择切换；SurfaceTool 合批导致连续转镜约 44.9 ms。当前使用完整构件简化、即时快照与预缓存数组合批。这些失败记录不作为最终通过证据。
