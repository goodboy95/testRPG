`[计划]` 依第一章细案开始场景和对白草稿，无须先为有意留白的悬念编造真相：

4. 细化文档内配角称呼、普通工具外观、交互节奏与合理报酬草稿；不创建运行时 ID，不擅自命名外地目的地。

完成条件：作者能按任务卡解释入口、动机、行动、交差结果、后续条件和中断恢复；玩家不需要知道后台链结构也能找到事情做。第一章生活阶段有帮助人的实际结果，章末无解仍能自然暂停。

## 后续运行时接入门槛

`[计划]` 当前不执行下列制作：

1. 先确认场景文本和结果，复用已接入的梦境成功／刺醒入口，再设计第一章阶段时间、后台任务发布、接取/交差/应付/领取以及跨章继续的接口与存档兼容。禁止复用旧 `slice.*` 或文档卡片编号表示新运行时语义。
2. 保持[架构](../engineering/architecture.md)中唯一 GameState 与 Core 所有权；评估现有导演和 `MainController` 职责，不在文档轮次重构。
3. 先 Core 与测试，再按[内容制作规范](../engineering/content-authoring.md)同步 JSON、独立对白、本地化、角色日程、场景和资源。
4. 先验证一条正常委托的完整接取/交差/结款，再覆盖多链交错、两战、提前问箱、取消恢复、低关系和跨章去重；第一章全真条件与独立支线均需有测试。
5. 第二章学校事件和离村入口在各自设计完成后制作；旧公司路线与终战职责不是待执行清单。

每条实际制作的事件链交付：状态与 ID、内容/资源引用、规则和内容测试、场景冒烟、人工路径记录、当前实现与文档更新。没有可玩内容不得填“已实现”。
