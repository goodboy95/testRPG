## 叙事边界

- 新游戏在姓名确认后直接进入第一室·旧教室；走出房门才发现四室连接在洋房公共空间中。标题、HUD、背包或确认框均不使用“梦境”“醒来”“跳过”等揭示词。
- 第一室只有主角；第二室器材间打开后，主角与林晓雨初次见面，此后共同移动。双方在现实中此前从未见过。
- 大头针确认只警告“永久失去尚未弄清的信息”。确认后才揭示梦境，清空梦境物品并永久结束本周目奖励资格。
- 出口开启是第一阶段机制里程碑，不是正式逃出；不得生成占位信息、现实纸条或 `CompletedEscape`。

## 背包、记录与提示

- 梦境背包与现实 `InventoryState` 完全分离。普通物品只展示名称、图标和说明，不存在选中状态；大头针保留独立的“对自己使用”。
- 初始常驻大头针不可丢弃；其余当前目录物品按谜题链获得。消耗品仅在正确目标成功使用时移除。
- `I`、`Tab` 或 Xbox `X` 打开分页面板。救出林晓雨前只有“物品/记录”，加入后才出现“与晓雨商量”。记录保留已观察事实与声音/颜色的文字、形状或波形替代。
- `Tab` 使用真实 Tab 键值，不再与 Backspace 共用或误绑；背包开关在梦境输入前置阶段处理，因此即使分页按钮持有焦点也能再次按 `Tab` 关闭。
- 检查机关时，Core 按稳定“目标→道具”目录自动使用背包中全部匹配部件；多槽机关一次装入当前持有的全部部件，齐全后同次打开面板或启动。部分安装会保存，错误区域、缺前置、无匹配和重复操作不消耗物品。
- 顶部不显示任务目标、当前道具、镜头说明或晓雨头像，只保留左上角紧凑区域名。新游戏首次进入第一室前显示一次阻塞式操作提示，说明 Esc、I/Tab 及 Xbox Menu/X；读档和换房不重复。
- 林晓雨加入前 Core 与 UI 都不提供提示。加入后，每个已发现未解机关有 0–3 级：目标提示、关联提示、近答案提示，无惩罚。
- 谜题面板使用可聚焦按钮、逐项撤销、清除、取消和确认操作；数字锁支持数字键直输，字号继承 100%–150% 设置。
- 3D 游玩时鼠标常驻捕获并隐藏；Esc 打开梦境暂停，背包、谜题、确认框、转场或窗口失焦会显示指针并锁定世界输入。关闭模态后恢复捕获；若指针意外可见，点击游戏画面可重新捕获。暂停菜单提供继续、设置、返回标题和二次确认退出；标题页同样可正常退出。

## 美术表现

- `[已实现·待人工终验]` 第一室是 12×9×4 米、带完整天花板的四墙房间，含关闭教室门、三组西窗、完整教学区、教师桌、地图柜和十八组共享网格课桌椅。当前 v5 使用扫描 PBR、真实结构分层、中尺度五金、非对称书纸陈设、Filmic 和冷暖分区照明；灯具、吊扇、广播、线槽、清扫工具和装饰物均不产生假线索。
- `[已实现·待人工终验]` 原 2D 走廊已替换为 3D 英式工艺美术风洋房前厅与完整内廊：内廊净宽约 6.8 米、长约 18 米、净高约 4.2 米，包含四室门、锁闭双叶大门、两个无交互的未来扩展实墙模数，以及完整护墙板、壁炉、地毯、玄关家具、壁灯、画框和旧住宅陈设。当前内廊 v2 使用扫描 PBR、Filmic 和冷暖分区照明；完整外观 v1 另行导出用于离线验收和未来复用，游戏不加载外观。
- `[已实现·待人工终验]` 第二室是约 11×8×4 米程序化 PBR 3D 音乐教室，含 18 个唯一交互点、16 组碰撞、两个 ReflectionProbe 和冷暖灯。第三室是约 12×9×4.2 米档案兼广播室，第四室是约 18×13×7.5 米旧礼堂；两室分别加载 v1 GLB、各有 15 个唯一目标、独立 Godot 碰撞、Filmic、冷暖实时灯和 2/3 枚 ReflectionProbe。
- 镜头正式采用方案 A：FOV 60°、固定约 21°俯角、3.4 米 SpringArm、1.30 米跟随高度与 0.22 米肩偏的跟随式透视第三人称。鼠标水平移动或手柄右摇杆可连续 360°环绕，垂直观察锁定，不自动跟随角色朝向回正。移动始终按屏幕方向解释，镜头朝向不写存档。
- 当前自由第三人称模式始终保留四面墙，不再执行近墙裁切或淡入淡出；SpringArm 在墙体与家具前缩短镜头距离以避免穿模。旧四方向相机、双墙裁切控制器和着色器只保留作历史实验对照，不由第一室场景加载。
- 第一室不使用悬浮文字。接近目标时显示暖琥珀地面光环；高对比设置显示黑色外圈与白色内圈，操作文本仍由底部提示承载。
- 新游戏使用第一室前部偏右的安全出生点 `(448, 214)`，默认朝向黑板；该点不与家具碰撞、不处于任何初始可用交互点的 1.25 米范围内，并让方案 A 的 SpringArm 完整伸展。已有梦境存档坐标不重置。只有从洋房返回第一室时，才使用教室东门内侧的门口安全点。
- 主角使用 `CharacterBody3D` 和竖直胶囊碰撞；洋房与四室的墙、关闭门和主要家具均使用独立 `StaticBody3D`。SpringArm 对墙和家具做体积扫掠，玩家自身从检测中排除。房门交互后锁定输入、开门、淡出并直接换场；玩家不能自行穿过门洞或走到模型外。洋房与四室之间均使用对应门口安全点并保持 Orbit 3D。
- 梦境长期状态仍只保存稳定区域 ID 和二维 `PositionX/Y`。来源＋目标区域决定门口出生姿态；第一室和洋房各自把存档坐标映射到 X/Z 平面，旧坐标若落入新障碍物则解析到最近安全点并保存修正。镜头相对门朝向只作为临时换场上下文，不写入存档。
- 四室机关外观直接由 `DreamEscapeState` 派生，不保存第二份持久表现状态；面板预览和晓雨左机关/录音机协作姿态由 `DreamAreaTransientState` 传递，关闭、离房或重载即清零。当前工作副本在全部 3D 区域默认使用本机非商业 `mc_model` PBR 角色和 `idle/walk/jog`；资源缺失、干净检出或发布导出时回退到原有四向精灵表 Fixed-Y `AnimatedSprite3D` billboard。晓雨在后三室使用跟随、超距回位和短时脚本姿态。
- 第一室保留 `classroom-mvp`、v2、v3 和 v4 作为灰盒/历史/候选对照；当前运行时权威源是 `classroom-art-pass-v5.blend`，场景加载 `classroom-art-pass-v5.glb`。洋房内廊当前权威源为 `dream-manor-hall-v2.blend`，场景加载同名 GLB；v1 内廊保留为历史基线。`expand_environment_cinematic_full.py *-check` 只读检查完整细节集合，`export_environment_cinematic_samples.py *-check` 临时复导并验证节点、预算和哈希。
- `[计划·v2 静态候选技术检查通过，待视觉确认]` 半写实 3D 主角继续以 Blender 官方 Human Base Meshes v1.4.1 的 CC0 男性人体为离线起点。v1 未绑定技术样模只保留作尺度/导出基线；正式身份锚点、脸发细节板和服装细节板已进入 provenance。原画式 v2 静态 GLB/manifest 已按 `1.69±0.02m` 普通偏瘦体格完成技术导出，并以 `1.7017m`、`34972` 三角面、6 个网格、1 个材质面、无 Armature/Action 的结果通过只读检查；manifest 仍为 `runtimeReady=false`。候选未获负责人视觉确认前，不进行其绑定、`idle/walk/jog` 动画或 Godot 接入；当前本机 `mc_model` 覆盖是独立的非商业占位，不构成 v2 视觉批准，也不改写剧情圣经中的正式身份锚点。
- 游戏运行和正式构建不依赖 Blender。采用资产、版本、结构参数、哈希、许可证和后处理统一记录在 provenance 与各自 manifest。

## 状态与结算

`DreamEscapeState` 以内容版本 5 保存当前区域/坐标、34 件物品目录中的持有项、已解机关、开放区域、线索、提示等级和晓雨加入状态。进行中的 v4 梦境档明确拒绝；已完成 v4 终态与无梦境 Legacy 档继续兼容。状态机预留：

```text
InProgress -> ExitOpened
InProgress -> PinPendingWake -> CompletedPin
预留：EscapePendingWake -> CompletedEscape
```

第一阶段正式产生的终态只有 `ExitOpened` 和 `CompletedPin`。旧 v1 存档没有 `DreamEscape` 字段时按 Legacy 两日切片载入，不提升存档格式版本。
