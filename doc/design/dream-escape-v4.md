## 叙事与边界

`[已实现]` 玩家逐步认识一次未完成合演中被节目单遗漏的幕后合作者。节目单只列台前，准备清单、值日票、合影和工作票保留开门、校准、传谱、侧台收尾的贡献。同一种勾记连接材料；姓名、年代和现实原型不作结论。

`[固定约束]` 第一室仅主角；第二室隔门交换观察，开门后互报姓名、决定同行。2026-09-12 负责人确认两人在现实中是见过或听说过、但没认真交谈的同村人，梦中为第一次深入合作；本轮不改已有对白和机制。上述旧事只保存在梦中记录；不增加 `Facts`、`Evidence`、`Leads` 或关系值。新流程仍止于 `ExitOpened`，封存排列、梦境揭示、醒后纸条与现实承接属于后续制作。大头针已有路线继续保留。新第一章晓雨现实不出场，方向见[醒后剧情流程](story-flow.md)。

## 线索与提示

`[已实现]` 外部纸面线索和对应机关继续使用不同交互点；分离配对保持至少 2 米。已调查材料可从独立梦中记录和现场检视重复阅读；机关内的“关联资料”已移除。隔门编号、晓雨第四波形属于必要合作信息，免费提供；已记录的侧台条件可重复阅读，独立于三级求助。

`[已实现]` 题面只描述装置与操作，不列解法。晓雨加入前，失败触发主角思考：没有相关材料时表达疑惑；部分材料时可以回想已见部分；齐全时也仅提醒材料关联，不说完整操作。加入后自动失败只给简短自然反应；主动商量依次引导观察、联系材料、提出局部试探建议，三级合计也不提供完整答案。必要图形、文字和合作信息不删减，不要求听力、色觉或乐理。详见[角色提示规则](../engineering/puzzle-feedback.md)。

## 状态、稳定 ID 与对白

`DreamEscapeService` 负责成功判定、消耗、装配、奖励与剧情完成资格；`DreamEscapeState` 保存物品、安装槽、观察、已解节点和加入状态。新增 `DreamPrologueCatalog` 定义 12 组及剧情资格，`DreamStageRules` 为预览和提交共享双视角约束。

新语义节点为 `dream.music.channel_calibration`、`dream.music.backstage_photo`、`dream.archive.retrieval`、`dream.archive.work_timeline`、`dream.auditorium.stage_alignment`、`dream.auditorium.tape_reconstruction`、`dream.auditorium.handoff_plan`。旧转译、缓存、重复控制台 ID 保留在退役目录，不可提交或复用。装配使用 `dream.assembly.metronome` 与 `dream.assembly.fuse` 标记，不算额外主谜题。舞台钩杆、琴凳夹钥、检视镜退出活动物品目录。

`[已实现]` 内容版本升为 6，外层存档格式仍为 1。较旧版本的进行中和 `ExitOpened` 梦境档要求重开；真正 `CompletedPin`/`CompletedEscape` 且背包清空的终态、无梦境 Legacy 档保持兼容。

`DreamAreaTransientState` 只携带预览、晓雨按压和实际交接步骤；不写存档。关闭机关、进入其他模态、离房或重新加载会解除交接。持续场景外观从 Core 派生，未提交试调不会永久改变配重。最后排演是持久解题结果，实际四步执行可反复尝试。

`[已实现]` Dialogue Manager v3.10.4 已 vendored，来源和本地兼容补丁见 `addons/dialogue_manager/TOWN_RPG_VENDOR.md`。序章 13 个独立 `.dialogue` 由 `DreamStoryPlayer` 经插件遍历，沿用现有 `DialoguePanel`。每个文件只有一个对应 `complete_event`；遍历时跳过逐行 mutation，抵达 END 后由 Core 原子提交一次 `eventId.complete`。取消不完成事件，重进可重播；恢复 `ExitOpened` 时先补完未读交流再显示机制完成页。八个 Legacy 事件的旧演示编排仍待另行迁移。
