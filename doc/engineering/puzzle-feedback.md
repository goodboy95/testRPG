# 解谜文案与角色提示

2026-09-09。`[已实现]` 当前序章四室及洋房采用下述规则。调整来自项目负责人确认；谜题答案、物品链、剧情、内容版本 6 与存档格式 1 不变。

## 写作边界

- 题面描述眼前装置、目标与操作方式，不写完整解法、正确排列或推理步骤。独立纸面、现场图形和合作观察仍提供原始信息，不能为了隐藏答案删掉可解性条件。
- 缺工具、尝试失败和准备不足使用角色口吻。拾取、安装成功可用简短客观反馈；资源、存档或对白读取错误仍明确报告实际问题。
- 机关内不再提供“关联资料”、文档侧栏或资料分页。玩家通过独立梦中记录、现场检视回看材料。器材间音板仍直接显示门后女孩读标签的现场对白；声学校准的“一起观察”、舞台正面/侧台及图形文字替代继续保留。

## 自动思考

晓雨加入前：没有相关材料时表达疑惑、建议再调查；有部分材料时仅回想实际见过的那部分；材料齐全时也只提示相关材料可能有联系，不讲计算、对应方式、正确位置或操作顺序。

`DreamThoughtRules.Select(state, context, result)` 是纯 Core 只读规则。只有 `Changed=false` 且错误键属于解谜失败白名单才返回 `DreamThoughtSelection`；成功、已解、重复观察、已安装、无效区域和求助上限不会被当成错误答案。`Knowledge` 为 None / Partial / Complete，不决定提交资格。

23 组上下文覆盖 19 个规则节点及节拍器装配、保险丝装配、房门、母带播放器，另有无具体上下文时的通用反馈。相关材料由 `PuzzleInputClues` 与各装置物品记录组成。`DreamThoughtMemory` 可由已发现线索、当前物品、安装槽或已完成步骤证明；例如钟针装入后移出背包，仍可回想，组装保险丝后仍记得使用过的材料。新材料或安装方式必须同步这些证明条件与完整性测试。

同一材料在不同语境下可以有独立文案，例如黑板与蒙尘谱面的粉笔、时钟与密码锁的交接便签。当前 214 条情境文案，每个适用分支至少两句。`DreamEscapeController` 按当前候选集合轮换，标注玩家姓名，显示在原短提示区；轮换只在内存中存在，重建场景后重新开始，不写存档，不推进 `HintLevels`，不会随着失败次数升级为答案。

时钟和值日表只安装了部分物品时，先显示这次真实安装的结果；下一次检查若仍不足，再显示相应思考。同一次交互只显示一次结果，录音机不再追加第二条缺件清单。没有新物品或线索时也能继续调查、重新尝试。

晓雨加入后，自动失败只给简短自然反应，不自动推进深入帮助。互报姓名前的回想称“门后的女孩”，不提前使用姓名。

## 主动商量

三级求助资格、已请求等级与记录保持原有规则，无惩罚。三层文本统一为林晓雨的自然对白：

1. 提出观察方向。
2. 联系材料或指出值得比较的关系。
3. 试探性提出一个局部调整或判断，剩余部分由玩家推理。

不得把完整答案拆进三条回复中。比如舞台三级可建议 A 组先试三档，但不能继续列出其他配重和全部影盘顺序；教师桌可怀疑第一位与窗户有关，不能报出完整密码。单选题也不能用位置描述变相点出唯一正确项：合影三级只建议排除挡住通道的候选，剩下几个仍需比较。必要的隔门编号、第四波形、侧面条件与求助等级独立，继续免费重复提供。

## 验证

Core 测试覆盖无材料、部分材料、齐全、安装/消耗后的回想、加入前后、重复失败不变更状态，以及非失败结果的排除。内容测试检查全部情境键、有效材料证明、两个不同变体、19 个题面和 57 条求助对白；完整答案黑名单只补充人工逐题审核，不代表自动检测能理解一切剧透。

`DreamThoughtProbe.tscn` 走真实控制器和机关提交事件，验证姓名、已知材料边界、轮换、单次反馈、部分安装、三级求助、独立记录和所有机关无关联资料。可带 `--output=... --width=1280 --scale=1.5` 捕获画面；运行中抑制玩家存档写入。

实际命令、截图与未验收边界见[本轮验收](../production/dream-hints-validation.md)。真实玩家的自然感与难度仍需盲测。
